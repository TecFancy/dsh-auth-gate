# 中文写作规则

本文件约定本仓库中文文档的写法。术语的**唯一写法**在[术语表](terminology.md)，由 `npm run zh:prose` 执行机械部分；语义、语气和完整性由评审负责。

## 适用范围

- 所有 `*_zh.md` 和 `*.zh.md` 文档。
- `docs/history/` 下的历史文档**不适用**：它们冻结，不重译、不重排。
- `docs/i18n/terminology.md` 本身不适用（它是术语真源，不是正文）。

## 机械规则（`npm run zh:prose` 执行）

1. **全角标点**：中文正文用 `，。；：？！（）` 和 `「」`，不用半角 `,.;:?!()` 和 `""`。
   - 例外：代码块、行内代码、URL、文件路径、英文句子内部。
2. **直角引号**：引用用 `「」`，嵌套用 `『』`。不用 `""` 或 `''`。
3. **中英混排空格**：中文与英文/数字之间留一个半角空格。`用 npm run verify 检查`，不是 `用npm run verify检查`。
   - 例外：中文标点前后不留空格。
4. **数字**：正文用阿拉伯数字（`14 位`、`3 个`），不用中文数字，除非是固定说法（`一次`、`两段式`）。
5. **人称**：统一用「你」，不用「您」。
6. **专有名词大小写**：`GitHub`、`npm`、`TypeScript`、`WebAuthn`、`Cordis`、`dsh`、`DeepSeek Harness` 按此写法，不写成 `Github`、`NPM`、`Typescript`。
7. **术语表禁令**：术语表「不要译作」列里的写法一律失败。

## 语义规则（评审执行）

### 最小改动

改一份已有的双语配对时，只改需要改的那几段。不要为了「顺手统一」重译整篇。重译会让评审无法分辨哪些是这次的真实改动。

### 两遍自审

改完中文侧，读两遍：

1. **第一遍看事实**：每个数字、路径、命令、默认值是否与英文侧一致？英文侧删掉的段落，中文侧删了吗？
2. **第二遍看中文**：这句话是中文母语者会写的吗？有没有翻译腔（「这是被设计为」「进行一个检查」）？

### 结构必须一致

`npm run bilingual:check` 比较两侧的结构签名：围栏代码块逐字节、表格维度、列表种类和项数、链接目标（按 locale 投影后）。中文侧不能少一个代码块、少一行表格、少一个列表项。

翻译可以调整段落顺序吗？**不可以**。结构签名要求顺序一致。

### 不要翻译的东西

- 代码块内容（逐字节一致）。
- 行内代码里的命令、路径、标识符。
- 术语表里标「保留英文」的词。
- 机器 token：`# Agent Note: `、`Status:`、`Archived:`、`Legacy ID:`、`## Problem` 等标题。

## 检查清单

提交前问自己：

- [ ] `npm run zh:prose` 通过？
- [ ] `npm run bilingual:check -- --pair <stem>` 通过？
- [ ] 英文侧改了，中文侧跟上了？
- [ ] 中文侧改了，`bilingual:re-record -- <stem>` 重录了？
- [ ] 新术语进了术语表？
- [ ] 读起来像中文，不像翻译？
