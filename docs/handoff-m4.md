8. Logout regression: `POST /auth/logout?next=/` with the session cookie → 302 + `set-cookie: dsh_auth=; Max-Age=0`;

## 4. M4 implementation pitfalls (new session should avoid directly)

1. **`Buffer` has no base32** (Node 24 still throws `ERR_UNKNOWN_ENCODING`) — `totp.ts` self-writes
   encode/decode (~40 lines, RFC 4648, uppercase no padding). Unit-tested via round-trips.
2. **RFC 6238 Appendix-B vectors need `counter = floor(T/30)`**: the table's `T` is Unix _seconds_, not the
   counter. First test draft used `T * 30_000 ms` (treating T as the counter) and failed all vectors while the
   implementation was correct. Verify with RFC 4226 Appendix D (`counter=0 → 755224`) for the core HOTP.
3. **otplib@13 is async and has a ≥16-byte secret guardrail** (both for cross-validation and if ever used as a
   dependency): `generate({secret, epoch})` returns a Promise; `verify({token, secret, epoch, epochTolerance})`
   takes one options object and returns `{valid, delta}` — not `(token, options)` and not `{ok}`.
   Cross-validation script (throwaway, `/tmp/totp-crosscheck/verify.mjs`) exercises 6 RFC vectors + 200 random
   secrets×counters × (window ±1 hit + outside-window reject); **206 checks, bit-for-bit match**.
4. **`setHeader("set-cookie", ...)` twice overwrites**: when clearing the challenge cookie _and_ issuing the
   session in one response, pass an **array** (see `issueSession`'s `extraSetCookie`); a second `setHeader` call
   silently drops the first cookie. Integration tests assert both headers via `getSetCookie()` (not `get()`,
   which joins values with ", " and misleads `.split(";")` parsing).
5. **Test fakes must `String(value)` set-cookie arrays** — the endpoint test fakes store headers in a plain
   object; passing the array straight through breaks `.toMatch`/`.toContain` assertions. All 6 legacy
   password-endpoints fakes were normalized to `String(value)`.
6. **`exactOptionalPropertyTypes` bites object building in tests**: `{ method, cookie: undefined }` is a type
   error. Build options conditionally (see `post()` in `test/password-totp-harness.ts`).
7. **Line budgets (max-lines 250 / max-lines-per-function 80, blank+comment lines skipped)**: the shared
   harness (`MemTable`+`makeRes`+`makeReq`+`makeHarness` ≈ 210 lines) would push _every_ per-file copy over 250.
   M4 created `test/password-totp-harness.ts` **outside src/** and imported it from the two stage test files —
   vitest only auto-collects `src/**/*.test.ts`, tsc build include is `src` only, coverage include is `src/**`,
   and the slice script was taught to accept `test/` as a leaf target. Also: prettier refuses to keep
   multi-property object lines together, so merging TOTP deps lines in fakes does NOT reduce line count —
   compress real code instead (e.g. one-line `return Promise.resolve({...})`, single-line flush arrow).
8. **`describe` callback counts toward max-lines-per-function**: splitting integration tests into two
   describes (instead of one big flow describe) was required; keep each describe ≤ 80 non-blank lines.
9. **`features/totp/` had to be added to `FEATURE_SLICES`** in `scripts/verify-slice-boundaries.mjs` _before_
   the first file landed (unknown paths fail closed), and `src/cli.totp.test.ts` + `src/integration.totp.test.ts`
   to `ROOT_FILES`.
10. **`z.enum` does not exist in schemastery** (this repo's config validator): use
    `z.union([z.const("off"), z.const("optional"), z.const("required")])` like the existing `mode` union.
11. **never log codes or challenge cookies** (P23/M21): the smoke steps above print them for the fixture user
    only; production code paths never do.
12. **`test/` dir is new repo shape**: keep it as the single shared-test-harness location; do not copy
    harnesses back into per-file duplicates (they blow line budgets), and do not create helpers inside `src/`
    (they'd compile into lib/ and count toward coverage) — M3 pitfall 8's spirit is preserved, the location is
    new.
