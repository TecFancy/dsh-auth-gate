# scrypt 参数随哈希存储，验证按存储值重派生（2026-08-30 从 M3 回填）

## 决定了什么

口令哈希使用 Node 内置 scrypt，参数（模块常量 N=65536, r=8, p=1, keylen=32, maxmem 128MB）随每个哈希一起存储。验证时按**存储的参数**重派生而不是模块常量——升级参数后旧参数生成的哈希依然可验证。`dsh-auth user hash` 支持离线哈希。

## 背景

M3（口令模式）需要一种免依赖、可调参、且参数升级不会作废全部存量哈希的口令哈希方案。Node 的 `node:crypto` 原生自带 scrypt。

## 考虑过的替代方案

- **bcrypt / argon2**——拒绝：引入依赖（argon2 还需 native 绑定）；`node:crypto` 的 scrypt 零依赖。
- **只用当前模块常量验证**——拒绝：参数一升级，所有存量用户静默失效。
- **固定参数，靠重新登录迁移**——拒绝：公网门禁经不起「加固补丁=全员锁死」。

## 为什么这样选

参数随哈希存储让加固变成滚动变更而不是「零日事件」；按存储参数验证正是登录限速测试覆盖的路径（「旧参数哈希在新常量下仍可验证」）。验证侧做了基本恒时比较。
