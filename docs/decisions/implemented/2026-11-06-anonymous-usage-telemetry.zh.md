# 匿名使用统计：一次惰性上报，默认开、可见可关

## 决定了什么

本插件每进程每 24 小时最多发一次匿名使用统计，而且只在一次请求已经通过登录门之后。报文是两包
共享契约的 v1 形状，逐键一致：报文版本、从本包 `package.json` 读一次的包名与版本、一个随机安装
id（UUID v4）、Node 主版本、平台、架构，以及本部署的三个事实 - 门 `mode`、`totp` 模式与用户数
分桶 `users`。它是对 `https://t.hi-ruofei.com/v1/ping` 的一次 `POST`，带 5 秒中止信号，不重试、
不写日志，也不影响它搭载的那次请求。

`telemetry` 是普通、**可见**的配置项，默认 `true`；`false` 表示一个请求都不发。`installId` 声明
为 `.volatile().hidden(true)`，首次使用时生成，经宿主 settings 服务（`ctx.get("settings")`）写回。
宿主不提供这个服务时，生成的 id 留在这个进程的内存里，照常上报 - 每次重启换一个新的，端点按
`(id, 当天)` 去重即可吸收 - 绝不退化到磁盘上的私有文件。`users` 指标是惰性读取的：只有上报真正
到期（至多每 24 小时一次）时才用登录路径同一个 `loadUsersFile` 读一遍，绝不给任何请求路径增加一次
读盘。

挂载点是守卫的放行分支（`guardHttp`、`guardResource`、`guardUpgrade`，经 `wrapServer` 把同一个
`AdmitHook` 接到每一类被守卫的入口）：钩子在 `decide()` 返回 `allow` 之后运行，不在判定路径上。
没有定时器，也不在启动时调用。

**关于「匿名」这个词。** 它是功能名，不是法律主张。准确的说法、也是两个 README 现在用的说法，是
**无 IP、以随机 install id 关联的伪名化数据**：同一个 id 在时间上可关联，所以这些数据只用来估装机量
和版本分布，不用于计费、安全判断，也不对外宣称精确数字。不采集 IP，端点除报文本身外不存请求元数据。

## 背景

驱动这个决定的是两个问题：有多少台机器真的在跑这个插件、它们升到了哪个版本。部署本身回答不了
这两个问题 - 自托管实例没有遥测，维护者数不出安装量。约束来自产品本身而不是测量手段：这是一个
安全插件，唯一职责是把人挡在门外，数据面不能变大；它装在运维者自己的机器上，常常离线优先，用户
选择自托管恰恰因为不想要厂商账号。两个包（`dsh-auth-gate` 与 `dsh-lingualab`）回答同一个问题，
所以共享一份线上契约与一个端点，任何一边的报文改动都是契约改动。

## 考虑过的替代方案

- **机器指纹**（主机名、MAC 地址、`/etc/machine-id`）：跨重启稳定，但它是可识别信息 - 把这次上报
  和一台机器在跨网络、跨账号的范围内绑在一起，还要按操作系统特权读取，正好破坏"匿名"这个承诺。
  否决。
- **第三方统计 SDK**（PostHog、Sentry、APM agent）：引入新依赖，自带后台定时器、自己的数据采集与
  升级面，而本包不允许新增依赖。整个需求一次 `fetch` 就能覆盖。否决。
- **账号或登录式统计**：需要服务器、注册与个人数据存储，等于"装一个登录门"就"在登录门厂商那里开
  一个账号"。否决。
- **默认关、用户主动开**：诚实，但样本会小到回答不了促成这个功能的问题；安装量恰恰是本仓库在本地
  推断不出来的东西。改为「默认开但可见可关」。
- **把 `installId` 写进 `$DSH_HOME` 下的文件**：给一个配置里本来就有的值安排第二个家，第一次被手工
  编辑两边就会打架。settings 服务写回的就是加载时读的那份配置；服务缺席时 id 留在内存。否决。
- **把钩子挂进门的 `decide()` 或会话层**：那会把网络或 id 生成放到认证判定路径上，一次失败或一次慢
  写就能伤害唯一不能退化的东西。守卫的放行分支在判定之后、判定之外。否决。
- **启动时就上报**：起来了但从没被使用的实例会被算成"在用"，每次重启都像一次新安装。回到"只在放行
  请求之后"才诚实。否决。

## 为什么这样选

默认开才让数字有意义；可见可关才让同意是真的 - `telemetry` 是配置表里的一行普通选项而不是隐藏字段，
一个键就能关掉整条链路。惰性放行之后才报，把上报绑在真实使用上：起来了但没有任何请求被放行的进程
什么都不发，也没有任何东西按计时器运行。报文只由本部署的配置与进程事实组成 - 永远不含用户名、口令
哈希、TOTP 密钥、会话 id、token、客户端 IP、请求路径或主机名 - 所以插件的威胁模型没有变化。没有依赖、
没有账号、没有我们自己的服务器，而且所有失败都被吞掉：匿名上报永远不能失败或拖慢一次认证判定。
