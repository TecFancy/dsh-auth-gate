# D15. 登录页视觉语言：冷中性检查点卡（保留反钓鱼身份块）

## 决定了什么

`src/shared/login-page.ts` 的三变体共享样式改为「冷中性 + 柔和层次 + 发丝分隔线 +
域名当主角」：浅色底 `#eaedf2 → #dde2ea` 渐变、卡片 `#f6f7fa` + 1px 边框 + 一层
柔和悬浮阴影、输入框内凹 + 10px 圆角 + 150ms 过渡、主按钮近黑。信息结构上把
kicker + 域名标记 + host 收进 `.head`（底部一条发丝分隔线），页脚 `.meta` 上方再加
一条；域名升到 22px/700/-0.025em 并前置一个 7px 中性方标记（`aria-hidden`）。
反钓鱼身份块（kicker / host / who / 换账号回退）、零第三方资源、无 JS 可提交、
深浅色、减少动效、6KB CSS 预算这些约束一条未动。

## 背景

2026-09-17 那版是「暖纸色 + 无阴影 + 小圆角」的工具站观感（`--bg:#f4efe6`、
`--surface:#fbf8f3`、单层 border），反钓鱼身份块本身有效，但主人看过后反馈
**「当前看起来稍微有点复古了」**。同一轮还确认了身份块的 host 来源问题（见 D14）。

## 考虑过的替代方案

- **保持 09-17 观感不动** —— 功能没问题，但「复古」这个观感判断是产品主人的直接
  反馈，且登录页是唯一面向使用者的一屏。
- **回到上游品牌蓝 + 盾牌 logo** —— 正是 09-17 改版刻意去掉的：与上游聊天产品的
  登录页同构会削弱反钓鱼语义（用户应把它读成「我的实例的门」而不是「DeepSeek 登录」）。
- **通用 SaaS 现代风（紫蓝渐变/玻璃拟态/大圆角）** —— 现代但无差别，且 AI 味重，
  与本项目「克制、可审计」的调性不符。
- **grok-4.6 三路候选里的单一路线**：
  - A 编辑式排印（白卡 + 发丝线 + 等宽域名）：最干净，但缺少层次，卡片与背景几乎
    融在一起；
  - B 柔和层次（冷石板 + 环境阴影 + 内凹输入）：观感最当代，但身份块的存在感不足；
  - C 检查点控制台（点阵底 + 全等宽 + 琥珀顶盖）：最「受控入口」，但满屏等宽大写
    对日常登录偏重。

## 为什么这样选

以 B 为底把「复古」治干净（层次、过渡、内凹控件都是 2026 年系统级 UI 的语汇），
取 A 的发丝分隔线建立信息分区（身份区 / 表单区 / 页脚三段），取 C 对域名的强调方式
把身份块重新立成视觉锚点——这正是这个页面的安全职责所在。三路候选都由 grok-4.6
并行出稿（各自给出完整自包含 HTML，均满足零外部资源与 CSS 预算），再在隔离实例里
真实渲染截图对比后定稿，取舍有据可查而不是拍脑袋。

遗留：域名前的方标记只有「实例身份正在展示」的装饰语义（`aria-hidden`，不进入可访问
树），**不表示认证已经完成**；若将来要表达更强状态（例如已绑定 TOTP），需要单独设计
并保证语义诚实。
