# 认证门失败即关闭（fail-closed）（2026-08-30 从 M2/M3 回填）

## 决定了什么

无法确认凭证时门恒 deny：credentials 服务缺失 → 恒 deny；token/凭证解析失败 → 按「无凭证」处理；无论服务是否可用，守卫照常挂载。失败在日志中响亮（loud），绝不静默。

## 背景

M2（共享 token 门）与 M3（口令门）期间实施。harness 并行挂载插件行，本插件 apply 时 credentials 服务可能尚未就绪；配置错误的部署上存储服务可能缺失。部署目标是公网 dsh 实例。

## 考虑过的替代方案

- **服务缺失时放行（fail-open）**——服务不可用时跳过守卫。拒绝：公网部署无认证等于裸奔。
- **服务就绪后才挂门**——拒绝：并行挂载下就绪时序有竞态，就绪前窗口无守卫。

## 为什么这样选

认证失败的代价不对称：误锁可以由运维人工解开，误放无法追回。因此 token 解析器每次操作现取（不做缓存），每次解析失败 log.error 后返回 undefined——门与「无凭证」完全同路径 deny。
