# 守卫包装 webServer，而不是 fork（2026-08-30 从 M1 回填）

## 决定了什么

登录门通过在插件内包装 `webServer` 服务的四类入口（路由表注册、upgrade 注册、fallback 注册、分发）实现，外加启动自检 `assertGuarded`（fail loud）。不改 dsh web 宿主本身。

## 背景

M1 需要对每个页面、每个 API 调用、每条 WebSocket 连接强制过门。`webServer` 由 dsh web-app 组合提供；当时上游没有契约中间件钩子。

## 考虑过的替代方案

- **fork dsh-web-app 把门加到上游**——拒绝：fork 与上游永久分叉，每次 dsh 更新都是一次合并。
- **靠注册顺序/前后注册**——拒绝：插件 apply 之后注册的路由会绕过门；四类入口全包装才能让插件对一切入口有最终决定权。
- **不做自检**——拒绝：对认证插件来说，静默未挂载的部署是最糟的失败模式。

## 为什么这样选

包装是插件能交付的最小侵入面：包装返回 disposer 精确还原包装前状态，apply 之后才注册的路由也会被包装后的 register 路径拦截。启动自检把「静默未挂门」变成「启动即报错失败」——这是 fail-closed 门的 fail-loud 搭档。
