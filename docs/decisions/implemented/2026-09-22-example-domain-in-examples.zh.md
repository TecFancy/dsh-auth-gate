# D16. 示例域名一律用 example.com（真实部署域名不随包发布）

## 决定了什么

仓库内文档、部署样例、测试与代码默认值里的真实部署域名一律换成文档保留域名
`dsh.example.com`（隔离实例写作 `dsh-test.example.com`）；`dsh-auth-proxy` 的
`--target` 默认值随之从真实域名改为 `https://dsh.example.com`。规则写进
`docs/specs/development.md` 的约定：真实部署域名不进入仓库，也不出现在随 npm 发布的
产物（`lib/`、`docs/demo/`、`.agents/skills/`）里。

后续（D17）：那个默认值被移除，`--target` 改必填。

## 背景

本插件是自用部署的产物：`docs/deployed/*` 记录了线上 Caddy + systemd 拓扑，早期文档、
部署样例与代理 CLI 的默认 `--target` 直接写了真实公网域名。域名是公开可解析的入口，
公开仓库里带上它，等于把「这台实例存在、以及它的部署形态」一并发布出去；随包发布的
`lib/proxy-cli.js` 还让任何以默认参数运行 `dsh-auth-proxy` 的人把流量指向作者的服务器。
`docs/demo/*.png` 截图此前存在同样的泄漏，已随 D15 改版重录为示例域名。

## 考虑过的替代方案

- **只改文档、保留 CLI 默认值** —— 真实域名仍随 `lib/proxy-cli.js` 发到 npm，泄漏面
  没变，而且默认值本就不该指向别人的生产环境。
- **把 `--target` 改成必填（去掉默认值）** —— fail-closed 语义更彻底，但属于 CLI 行为
  变更，既有调用方升级后会直接报错；留作后续独立决策，本次只替换默认值的取值。
- **加一条门禁脚本扫描真实域名** —— 脚本自身必须写下被禁字符串，等于把要藏的东西放进
  仓库；改成正向白名单（只允许 example.com / 回环 / 少数已知站点）又过于脆弱。改为
  约定文档写规则 + 评审人工把关。
- **重写 git 历史抹掉旧域名** —— 历史是已公开的事实，改写会给所有克隆者制造分叉，
  收益只是心理上的。

## 为什么这样选

`example.com` 是 RFC 2606 保留给文档的域名，永远不会指向真实服务，「仓库里不出现真实
域名」由此变成一条一眼可验的规则；顺带修掉一个真实缺陷——公开包不该把默认流量引向作者
的生产环境。代价是默认参数下的 `dsh-auth-proxy` 必然连接失败，这比静默代理到别人的
服务器安全得多。
