# Agent Notes

[English](README.md) | 中文

这里存放一类设计文档。**Agent Note** 记录影响本代码库的决策或提案：代码
和文档无法承载的*为什么*以及*放弃了什么*。本文件规定 Agent Note 存放在哪
里、何时需要写一份，以及文件内格式。

模型照抄 deepseek-harness 的 `.agents/notes` 树：四生命周期、六分类的决策
笔记系统，人只抽查、机器严格校验。

## 布局与命名

每篇 Agent Note 有两个维度，都编码在**路径**里，`{生命周期}/{分类}/yyyy-mm-dd-话题标题.md`：

- **生命周期**（顶层目录）即笔记的状态；状态变了笔记就在目录间移动：
  - **`proposed/`**：实现前待评审的提案；尚未构建（或只构建了一部分）。
  - **`implemented/`**：决策已落地。文件记录「定了什么、否了什么」，并**与
    实际落地保持同步**：后来代码挪了文件、改了名、换了 key/默认值，就在同一
    次改动里更新笔记（只改事实，路径、名称、结构，不改决策本身）。
  - **`rejected/`**：提案被考虑后否决。只有当它的理由还能拦住一个有诱惑
    力、会造成实际错误的念头时才保留；否则整组三件套一起删。
- **分类**（嵌套目录）即决策的*种类*，见下文[分类](#分类)。

文件名里的日期是话题**首次提出**的时间（以 git 历史为准）。笔记间的交叉引
用使用相对 markdown 链接（`[话题](../../implemented/architecture/2026-…-….md)`），
绝不写裸文本或编号，这样可机械校验、搬家不破。

活动生命周期树就是工作清单：直接浏览各生命周期/分类目录或搜索仓库即可。
树里**没有集中的 `INDEX.md`**，树本身就是索引。低未来价值的 implemented
记录移入独立冻结的 [`archived/`](archived/AGENTS.md) 树（见下文）。

## 生命周期迁移

笔记从 `proposed/`（面向未来的实质工作）或 `implemented/`（决策已定）起步，
状态变化时在目录间移动。**合法的迁移恰好是这些**：

| 从             | 到                                | 变化内容                                                                                             |
| -------------- | --------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `proposed/`    | `implemented/`                    | `## Proposal` 改写为现在时的 `## Decision`；提案期章节并入 `## Consequences`，计划按「实际落地者」丢弃 |
| `proposed/`    | `rejected/`                       | 在 `Status:` 行补上原因，文件冻结                                                                    |
| `implemented/` | [`archived/`](archived/AGENTS.md) | 三件套搬走；新增一行 `Archived:` 日期                                                                |
| `implemented/` | _删除_                            | 仅当被完全取代、且已并入当前拥有该决策的笔记时                                                       |
| `rejected/`    | _删除_                            | 当它不再能拦住一个可信的错误时                                                                       |

关于这些迁移，有四条事实从目录清单里看不出来：

- **`rejected/` 永不被归档。** 归档保存的是**已落地**决策的理由；被否决的笔记
  不记录任何已落地的决策，因此没有东西可冻结。被否决的笔记要么作为护栏保留、
  要么删除，见[归档](#归档)。
- **`archived/` 是终点。** 封存的三件套永久冻结，永不移动、永不改状态、永不
  回到活动树。
- **`proposed/` 绝不直达 `archived/`。** 只有 implemented 笔记能进归档。不再
  值得推进的提案应当被**否决**，而不是归档，见[何时写](#何时写)。从提案走到
  归档，需要把它的 `Status:` 改写成 `implemented`，而那等于宣称工作已落地，
  实际并没有。
- **计划在落地时被丢弃，而不是被并入。** `## Plan` 在 `proposed/` 与
  `rejected/` 合法、在 `implemented/` 禁止，所以这次迁移是**删掉**计划而不是把它带
  过去。门禁看不到这次搬家，它只看到目标快照里那个非法标题，见下一段。

门禁校验的是**快照，不是迁移**：它读当前树与每个文件的内容，从不读 git 历史。
所以「只有 implemented 笔记能进归档」的执行者就是 `Status:` 行本身，`archived/`
里的文件必须声明 `Status: implemented`，而任何如此声明的文件都会被接受，无论它
从哪来。**来源无法从快照机械校验**，这正是上面把迁移规则写在这里作为**政策**
的原因：一篇笔记是否经由合法路径抵达其目录，是一个**评审**问题，回答它的是 git
历史。`## Plan` 受同一条不对称支配：门禁检查的是这个标题**此刻**在哪个目录里，
而不是这篇笔记是否经由合法路径到了那里。

## 分类

每篇 Agent Note 属于 `scripts/check-notes.mjs` 里封闭集合中的一个路径编码
分类；分类门禁拒绝其他文件夹。新增分类需要同步更新该集合和本节。

| 分类             | 覆盖范围                                                                    |
| ---------------- | --------------------------------------------------------------------------- |
| `feature`        | 面向用户或模型的新能力。                                                    |
| `bug-fix`        | 修正缺陷或堵上事故复盘暴露的缺口。                                          |
| `simplification` | 移除代码、行为或表面积，但不新增能力。                                      |
| `architecture`   | 关于**交付源码**的结构决策，包之间如何关联、运行时词汇表是什么。            |
| `process`        | 代码**外围**的工具、策略、流程，门禁、包管理器、vendoring，不是运行时行为。 |
| `testing`        | 测试基础设施与策略。                                                        |

architecture / process 的分界：**architecture** 讲我们交付的源码；**process**
讲围绕它的工具与流程。（`refactor` 故意缺席，它与 `simplification` 重叠，
后者的判别词「可观察行为变没变」已经覆盖它。）

## 何时写

改动落入下列**任一**桶，**必须**在同一 PR 里新增或更新至少一篇 Agent Note：

- 改变行为、架构、或跨文件/跨包的约定
- 改变流程、工具、工作流（门禁、脚本、CI）
- 改变测试策略
- 改变存盘 / 接口 / 配置格式
- 做了维护者日后可能重新问起的选择

重大未来工作的提案从 `proposed/` 起步；已经定了的决策直接进 `implemented/`。
选与决策匹配的分类目录（见上文[分类](#分类)）。更新已拥有该决策的旧笔记即可
满足规则，不要另起重复篇。

改动**豁免**仅限纯机械或纯局部、不改变行为/约定/结构/流程/理由的情况：错
别字、格式微调、文件挪位、不影响行为的重构。豁免改动不用写笔记也不用解释。

笔记**绝不允许**被改写成另一个决策：用新笔记取代它，两篇保持交叉链接。被完
全取代的 implemented 笔记可以并入当前拥有者后删除，前提是先保留每一份独有
的理由、替代方案、后果与验证，修好每一处入链，并在同一次改动里删除对应件与
一致性记录。部分取代不满足条件：两篇都保留并交叉链接。

## 文件内格式

### 头部块

每篇 Agent Note 的前三行严格是：

```markdown
# Agent Note: <title>

Status: <status>
```

后跟空行。`Status:` 值取三种形式之一，且必须与文件所在的生命周期目录一致，
门禁会交叉校验：

- `Status: proposed`
- `Status: implemented`
- `Status: rejected - <一句话原因>`

`archived/` 里的笔记是唯一的例外：它保留 `Status: implemented`，并在其**正下方
一行**携带 `Archived: YYYY-MM-DD`（见[归档](#归档)）。`Archived:` 是头部字段，
因此只有在这个位置、且只在 `archived/` 中才合法，出现在别处的日期行属于半归档
状态，门禁会拒绝；而正文里的一行匹配文本也不能充当头部字段。

状态不带日期也不带括号：文件名承载首次提出日期，其余都交给 git；"以修订形
式被接受"属于正文内容。否决原因是唯一带内容的状态，因为被否决笔记的结论就
是读者来找的事实。

### 正文骨架

每篇笔记正文以 `## Problem` 开头，动机，单独读也要成立。之后的内容取决于
生命周期；反复出现的章节只用下面的规范名，真正专属的技术章节（包拓扑、线
上契约、schema）可以夹在必需章节之间自由发挥。

#### `proposed/`

```markdown
## Problem

## Proposal

…bespoke sections…

## Alternatives considered

## Acceptance criteria

## Risks
```

`## Proposal` 是拟议的改动，允许用将来时，计划、迁移步骤、开放问题在未落
地前都属于这里。`## Acceptance criteria` 描述什么可观察状态算完成。
`## Risks` 覆盖可能出错的点以及改动明知放弃的东西。

笔记记录的是**决策，不是工作令**。`## Proposal` 说明将要改什么、为什么，
但不承载「改动将由什么材料构成」。有三种形状不进这棵树，因为它们是写给**执行者**的、
且在工作落地的那一刻就过期：改动即将写入的**整文件正文**（它属于真正写下它的那次提交）、
**编号的分步流程**、以及**命令配方**，配方指的是「把改动构建出来」的那一串命令。
**判断结果不算配方**：一条演示某条验收标准的命令、一份 migrates-from/to 的 fixture、
或一段缺陷复现，属于它所结算的那条验收标准。而后来读者判断这个决策所需要的一切都要留下：
选了什么、为什么、什么输了、怎样算完成、可能出什么错，以及改动所固定的**稳定契约**，
公开 API 形状、模块边界、以及线上/磁盘格式。生成分步工作令的规划工具尽可以在
本仓库之外生成它。

#### `implemented/`

```markdown
## Problem

## Decision

…bespoke sections…

## Alternatives considered

## Consequences
```

`## Decision` 用现在时描述已落地的现实，全文与它保持同步。`## Consequences`
记录这笔取舍**花掉**了什么又**买到**了什么。提案期标题在这里是口头禅，门
禁会拒绝：`## Proposal`、`## Plan`、`## Migration plan`、`## Acceptance
criteria` 不得出现在 implemented 笔记里。`## Testing`、`## Deferred`、
`## Related` 只要陈述现在时的事实就没问题。

#### `rejected/`

被否决的笔记就是冻结的提案：保留原有提案期章节（包括 `## Acceptance
criteria` 或 `## Plan`），结论活在 `Status:` 行。只有头部块、`## Problem`
开场、`## Proposal` 章节和下面的 Alternatives 强制要求适用。

### Alternatives considered - 必填

每篇笔记都带 `## Alternatives considered` 章节：每个真实存在的替代方案以及
它为什么输，每个替代一段加粗领起，或每个争议方案一个 `### Why not <X>?`
小节。没有记录「打败了谁」的决策会招来反复重议。

替代方案只记录，不发明。

### 生命周期间移动

哪些迁移合法属于**政策**问题，由[生命周期迁移](#生命周期迁移)回答；本节讲**机制**。
把文件在生命周期目录间移动，等于在同一次改动里更新 `Status:` 行并重新满足
目标目录的骨架，否则门禁拦下这次移动。具体说，`proposed/` → `implemented/`
要把 `## Proposal` 改写成现在时的 `## Decision`，把 `## Acceptance criteria`
和 `## Risks` 折叠进 `## Consequences`（或改成现在时的 `## Testing` /
`## Verification` 章节来固定现在的行为），把计划换成实际落地的东西。
`proposed/` → `rejected/` 只需在 `Status:` 行补原因并冻结文件。

## 归档

当已落地的决策已经完成、其理由不太可能指导未来工作时，把 implemented 笔记
归档。只要它的替代方案、所有权边界、负面保证、持久/线上语义、安全规则或重
启条件还有用，就保持活动。绝不给 proposed 笔记归档：过时的提案直接否决。

`implemented/` 与 `rejected/` 是仅有的两个有出口的生命周期，而两者不同，完整的
合法迁移集合见[生命周期迁移](#生命周期迁移)。过时的提案是被否决而非被归档。

归档按路径编码为 `archived/{分类}/yyyy-mm-dd-话题标题.md`；`implemented`
故意缺席，因为只有 implemented 笔记能进归档。一次归档改动要：整组搬走英文
/中文/伴生文件三件套、保留 `Status: implemented`、在两份语言文件里紧挨状态
行下方插入同一行 `Archived: YYYY-MM-DD`、重录伴生文件、用 `npm run archives:check -- --write` 封存新文件、修好或删掉入链。这
是归档期间唯一允许的内容改动。

`Archived:` 日期是笔记被归档的那一天，它**不能早于文件名里的日期**，后者是话题
首次提出的时间，而笔记不可能在存在之前就被归档。门禁会比较这两个日期，之所以
做得到，正是因为两者都存在文件里。

一旦封存，归档三件套就永久冻结。不要编辑、翻译、重排、更新、移动或删除它，
也不要把它当作当前行为的权威。在这里，冻结由机器强制：每个归档文件都由 `archived/manifest.json` 里的 SHA-256
封存，`check-archives.mjs`（`npm run archives:check`）会拒绝被编辑、删除、移动
或未封存的文件，也会拒绝丢失或改动了基线提交里已有条目的清单。`check-notes.mjs`
仍校验其形状，`check-bilingual.mjs` 仍维持其 sidecar 一致；`check-note-links.mjs`
不读取归档笔记里的出链，因为封存的笔记无法修复。活动正文仍可在有意引用历史时链入
归档笔记，这些入链仍会被检查。

## 双语配对

`.zh.md` 对应件按仓库的 i18n 约定（`docs/` 配对门禁）逐节镜像英文版的结
构。机器校验的头部标记（`# Agent Note: ` 与 `Status:` 行）原样保留英文。
格式门禁跳过 `.zh.md` 文件，一致性由配对门禁检查。两种语言同等权威。
